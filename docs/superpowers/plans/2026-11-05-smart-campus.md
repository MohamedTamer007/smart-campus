# Approved Smart Campus frontend plan

Approved in chat on 5 November 2026. Level 3. Implement sequentially on branch work without commits or external writes.

1. Foundation: React/TypeScript/Vite, shared accessible shell, Arabic/English and explicit demo adapter.
2. Accounts: login/register, verification/recovery, settings and notifications.
3. Maintenance: submission/tracking/edit/cancel and scoped staff workflow.
4. Lost and found: private search, registration, confirmed custody, recovery/reservation and bilateral delivery.
5. Administration: scoped dashboards, roles, departments and record-derived statistics.
6. Verification: all applicable scripts, independent cumulative review, rendered responsive/keyboard/state journeys and completion report.

Follow docs/SMART_CAMPUS_REQUIREMENTS.md and all 18 supplied visual boards. Backend authentication, persistence, AI and deployment remain outside scope. Use illustrated demo records only, visibly labeled. No live-success fallback. Missing real photo/directory/API/policies do not block demo work.

For each phase: write behavioral tests, observe failure, implement, run scripts and guard skills, independent read-only review, fix valid findings, rerun and exercise browser journey. Maximum three review rounds per phase/final. Stop for unresolved Critical/High or unexplained failures.

Proposed files: src/app shell/providers; src/components controls; src/services contracts/demo model; src/features/{auth,maintenance,lost-found,account,admin} screens; src/styles tokens; tests behavior; e2e browser journeys; docs handoff and coverage; FRONTEND_COMPLETION_REPORT.md verified evidence.
